# 发布说明撰写技能

本技能帮助你把零散的技术变更，整理成一份**面向最终用户**的发布说明。

## 与 changelog 的区别

- changelog 面向开发者，逐条罗列提交。
- release notes 面向用户，强调「这次更新能为你带来什么」。

## 撰写步骤

1. **收集素材**：从 git 历史、changelog、PR 标题或用户提供的说明中收集变更。
2. **按价值分组**，而不是按提交分组：
   - 🚀 **重点亮点**：用户最能感知的 1-3 个改进，放在最前面。
   - ✨ **改进**：体验、性能、易用性方面的提升。
   - 🐛 **问题修复**：用户可能遇到过的 bug。
   - ⚠️ **破坏性变更 / 升级提示**：需要用户采取行动的内容（如有）。
3. **改写语言**：去掉内部术语，用「你 / 你的」视角描述收益，而不是描述实现细节。
   - ✅「现在导出大文件的速度提升了约 3 倍。」
   - ❌「重构了 exporter 中的 buffer flush 逻辑。」
4. **结构模板**：

   ```markdown
   ## vX.Y.Z — YYYY-MM-DD

   ### 🚀 本次亮点
   - ...

   ### ✨ 改进
   - ...

   ### 🐛 修复
   - ...

   ### ⚠️ 升级提示
   - ...（无则省略此节）
   ```

5. **收尾**：附一句感谢用户的话，以及反馈渠道（如有）。

保持简洁、积极、以用户价值为中心。
